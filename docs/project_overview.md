# Project Overview — Bank Branch Performance Analysis

## Problem statement
Bank management needs one place to see how every branch is performing: revenue against target,
profitability, deposits, loan quality, customer growth and satisfaction. Data usually sits in
separate spreadsheets, so under-performance is spotted late. This project builds a database-driven
analytics application that consolidates the data, calculates consistent KPIs, and turns them into
explained, actionable insights.

## Objectives
1. Store branch, customer, transaction, loan, financial and feedback data in a normalised SQLite database.
2. Validate and clean incoming data before it reaches the database.
3. Calculate KPIs from one central module so every page reports the same numbers.
4. Provide interactive, filterable dashboards for managers (Streamlit + Plotly).
5. Generate rule-based insights and recommendations with the evidence behind each one.
6. Restrict access to authenticated managers with hashed passwords.

## Architecture
```
CSV / Excel  ─►  data_cleaning.py ─► data_validation.py ─► data_import.py
                                                             │ (single transaction)
                                                             ▼
                                                      SQLite (bank_performance.db)
                                                             │ parameterised SQL
                                                             ▼
                                                      analytics/queries.py  (Filters → WHERE)
                                                             ▼
                               kpi_calculations.py ◄── branch/financial/customer/loan_analysis.py
                                                             ▼
                                                      insights.py (rules → findings + actions)
                                                             ▼
                          app.py ─► login gate ─► sidebar (nav + filters) ─► views/*.py pages
```

| Layer | Folder | Responsibility |
|---|---|---|
| Configuration | `config/` | Paths, thresholds, colours, demo-data sizes |
| Database | `database/` | Schema, connections, transactions, integrity checks |
| Authentication | `auth/` | PBKDF2 hashing, login, lockout, session, setup CLI |
| Data pipeline | `analytics/data_*` | Cleaning, validation, import, data quality |
| Analytics | `analytics/` | SQL queries, KPIs, per-domain analysis, insights |
| UI components | `components/` | Styling, sidebar, filters, KPI cards, charts, tables, login |
| Pages | `views/` | One module per dashboard page |
| Utilities | `utils/` | Indian number formatting, report exports |
| Scripts | `scripts/` | Generate / seed / reset / back up / initialise |
| Tests | `tests/` | pytest unit, integration and Streamlit AppTest UI tests |

> The pages live in `views/` rather than `pages/` on purpose: Streamlit automatically turns a
> `pages/` folder into public navigation links, which would bypass the login screen.

## Types of analytics demonstrated
- **Descriptive** — totals, averages, distributions (KPI cards, tables).
- **Comparative** — branch vs bank average, region vs region, actual vs target, top vs bottom.
- **Trend** — monthly revenue, expenses, profit, deposits, customers, applications.
- **Diagnostic (basic)** — rules that explain *why* a branch is flagged (e.g. expenses rising faster than revenue).
- **Decision support** — recommended actions attached to each warning.

No predictive analytics or machine learning is claimed or implemented.

## Data source
All data is **synthetic**, generated by `scripts/generate_demo_data.py` with a fixed random seed (42),
so results are identical on every computer. Twenty branches across 18 Indian cities are each given a
deliberate profile (high/average/low performer, rising costs, high defaults, low satisfaction, fast
customer growth) so the dashboards have realistic contrasts. No real customer data is used; customers
are labelled "Customer 000123".

## Security scope
This is an academic/demo application, not production banking software. See the README
"Limitations" section for what a production system would additionally need.
